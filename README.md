# ESTELAR.SU — магазин привилегий и доната для Minecraft

Готовый к запуску сайт-витрина для продажи привилегий, кейсов и донат-валюты
вашего Minecraft-сервера. Заказчик получает:

- публичную витрину магазина (главная, правила, контакты, оферта, политика);
- закрытую админ-панель с входом через **Discord**;
- хранилище в **Supabase** (или локальные файлы для тестов);
- готовые места для подключения **платежной системы** и **API плагина**.

> Этот README рассчитан на нетехнического заказчика. Если что-то непонятно —
> переходите к разделу «Чек-лист запуска» и читайте его сверху вниз: всё
> поэтапно.

## 1. Что внутри

```

├─ index.html           ← главная страница магазина

├─ privacy.html         ← политика конфиденциальности

│  ├─ css/styles.css    ← все стили сайта (одно темное «золотое» оформление)
│  ├─ js/app.js         ← логика витрины (каталог, корзина, заказы)
│  └─ js/admin.js       ← логика админ-панели
├─ backend/             ← сервер на Go (Fiber). Раздаёт сайт + API.
│  ├─ cmd/server/       ← точка входа
│  ├─ internal/         ← бизнес-логика
│  ├─ data/             ← локальные файлы хранилища (если без Supabase)
│  ├─ db/supabase/      ← SQL-схема для Supabase
│  └─ .env              ← все ключи и настройки (см. ниже)
└─ README.md
```

## 2. Чек-лист запуска

### Шаг 1. Установить Go 1.25+

Сервер написан на Go. Скачать установщик: https://go.dev/dl/.

Проверить установку (Linux/macOS):

```bash
go version
```

В Windows: открыть **PowerShell** и выполнить ту же команду.

### Шаг 2. Скачать репозиторий

```bash
git clone https://github.com/KurumaOfficial/Site-Minecraft.git
cd Site-Minecraft
```

### Шаг 3. Настроить ключи и тексты в `backend/.env`

В файле `backend/.env` хранятся все настройки. Ниже — что куда вписать.

| Поле | Что это | Пример |
|---|---|---|
| `APP_NAME` | Название приложения для логов | `ESTELAR.SU Store` |
| `PROJECT_NAME` | Имя сайта в шапке/тайтле | `ESTELAR.SU` |
| `SERVER_NAME` | Имя сервера Minecraft | `ESTELAR` |
| `PROJECT_TAGLINE` | Описание под названием | `Официальный магазин ...` |
| `SUPPORT_EMAIL` | Почта поддержки | `support@estelar.su` |
| `DISCORD_URL` | Ссылка на Discord-сервер | `https://discord.gg/estelar` |
| `VK_URL` | Любая вторая социальная сеть | `https://t.me/estelar` |
| `OFFER_URL` / `PRIVACY_URL` | Ссылки на оферту и политику | `/oferta`, `/privacy` |
| `PUBLIC_SITE_URL` | Полный адрес сайта в проде | `https://estelar.su` |
| `ADMIN_REDIRECT_URL` | Тот же адрес (на dev — `http://localhost:8080`) | `https://estelar.su` |
| `HOST`, `PORT` | На каком хосте/порту сервер слушает | `0.0.0.0`, `8080` |
| `STATIC_DIR` | Где лежат `index.html`, `assets/` | `..` |
| `DATA_DIR` | Папка, где хранятся файлы при работе без Supabase | `./data` |

> 💡 В файле уже лежат **тестовые** значения. Перед продакшеном их обязательно
> заменить (особенно `SUPABASE_*`).

### Шаг 4. Создать проект в Supabase (рекомендуется)

Supabase — облачная база данных с готовой авторизацией через Discord.

1. Зайти на https://supabase.com и создать проект.
2. В разделе **Settings → API** скопировать:
   - `URL` → в `.env` поле `SUPABASE_URL`;
   - `anon public` ключ → в `SUPABASE_ANON_KEY`;
   - `service_role` ключ → в `SUPABASE_SECRET_KEY` (никому не показывать).
3. В **Authentication → Providers** включить **Discord** и вставить
   `Client ID` + `Client Secret` (см. шаг 5).
4. В **SQL Editor** открыть файл `backend/db/supabase/schema.sql` из этого
   репозитория, скопировать его содержимое и выполнить — это создаст
   таблицы `store_catalog_items`, `store_orders`, `store_promo_codes` и т.д.

### Шаг 5. Создать Discord-приложение для входа в админку

1. Перейти на https://discord.com/developers/applications → **New Application**.
2. Раздел **OAuth2 → General**:
   - в `Redirects` добавить `https://<ваш-сайт>/auth/callback`
     (на dev — `http://localhost:8080/auth/callback`);
3. Скопировать `Client ID` и `Client Secret` → вставить в Supabase
   (см. шаг 4, пункт 3).
4. Узнать **Discord ID** того, кто будет администратором:
   - в Discord включить «Режим разработчика» (Settings → Advanced);
   - правой кнопкой по своему профилю → «Копировать ID пользователя»;
   - вставить ID в `.env` в поле `ADMIN_ALLOWED_DISCORD_IDS`
     (несколько ID — через запятую).

### Шаг 6. Запустить сервер локально

```bash
cd backend
go run ./cmd/server
```

Открыть в браузере http://localhost:8080.
Витрина грузится сразу. Чтобы войти в админку:

- быстрый способ для разработки: нажать сочетание клавиш `→ → ← ←`
  на главной странице (это «секретный» жест) и войти через Discord;
- если в `.env` стоит `ADMIN_LOCAL_BYPASS=true`, то Supabase и Discord
  можно не настраивать — администратор открывается «просто так» (только
  для локальных тестов; на продакшене эта опция автоматически отключается).

### Шаг 7. Развернуть на боевом сервере

Любой VPS с Go подойдет. Минимальная схема:

1. Скопировать репозиторий на сервер (`git clone`).
2. В `backend/.env` указать боевые ключи Supabase и **обязательно** заменить
   `PUBLIC_SITE_URL` и `ADMIN_REDIRECT_URL` на ваш домен с `https://`.
3. Поставить **Nginx** или **Caddy** перед сервером, выпустить SSL-сертификат.
4. Запустить сервер как systemd-сервис:

   ```bash
   cd backend
   go build -o /usr/local/bin/estelar-server ./cmd/server
   ```

   и зарегистрировать `estelar.service` (пример — в разделе
   `backend/README.md`).
5. Открыть сайт по https://<домен>/ — витрина и админка должны работать.

> 🔐 **Безопасность**: после переезда на прод сразу выключите
> `ADMIN_LOCAL_BYPASS=false` (он автоматически блокируется при
> non-localhost URL, но лишний раз убедитесь). Никому не показывайте файл
> `.env`. Если ключи Supabase или Discord утекли — сразу пересоздать.

## 3. Где менять контент без программистов

Всё, что видит покупатель, редактируется **из админ-панели** (вход — Discord
из шага 5). После входа:

| Раздел | Что меняется |
|---|---|
| **01. Аналитика** | Просмотры, заходы по страницам, сводка по магазину. |
| **02. Заказы** | Очередь заявок: одобрить, отклонить, добавить комментарий. |
| **03. Каталог** | Названия, картинки, цены, описания товаров. |
| **04. Промокоды** | Скидки и лимиты использования. |
| **05. Контакты** | Тексты и ссылки в блоке контактов на главной. |
| **06. API** | Webhook-и для автоматической выдачи товаров (см. ниже). |
| **07. Оплата** | Выбор платежной системы (см. ниже). |

### 06. API — автоматическая выдача из плагина

Эта вкладка нужна, если у вас на сервере Minecraft есть плагин, который
умеет ставить привилегии / открывать кейсы / зачислять валюту по HTTP.

Что делает сайт:
1. Когда администратор переводит заказ в статус **«Выдан»**, сайт отправляет
   `POST` на указанный вами URL.
2. В заголовке `X-ESTELAR-Signature: sha256=…` едет HMAC-подпись общего
   секрета — плагин её проверяет, чтобы не принимать чужие запросы.
3. Если плагин ответил `200 OK` — заказ помечается как доставленный
   автоматически. Если нет — остается в очереди ручной выдачи (вы ничего
   не теряете).

Как настроить:
1. В админке открыть **API**.
2. Сгенерировать длинный секрет (например, `openssl rand -hex 32`) и
   вставить в поле «Общий секрет webhook».
3. Включить нужные категории (Привилегии / Кейсы / Валюта), указать URL
   плагина и `Bearer`-токен (опционально).
4. Кнопка **«Тестовый запрос»** отправляет пробный POST — так вы сразу
   видите, отвечает ли плагин.

Тело webhook-а (пример):

```json
{
  "event": "order.issued",
  "orderId": "ESTELAR-20260426-A1B2C3D4",
  "category": "privilege",
  "productSlug": "vip",
  "productName": "VIP",
  "nickname": "Steve",
  "periodCode": "30d",
  "quantity": 1,
  "finalPrice": 199,
  "currency": "RUB",
  "sentAt": "2026-04-26T20:00:00Z"
}
```

### 07. Оплата — заготовка под платежную систему

Сейчас сайт работает в режиме **«Ручная выдача»**: покупатель оставляет
заявку, администратор подтверждает её. Это безопасный стартовый режим.

Когда вы получите ключи у платежного провайдера, в админке во вкладке
**Оплата** выбирается провайдер (ЮKassa / CloudPayments / Lava /
Tinkoff Pay), вписываются `Shop ID`, `Secret Key`, `Webhook URL`, и заказы
начнут уходить в боевой провайдер. **Без этих ключей сайт остается в
режиме ручной выдачи и ничего не ломается.**

## 5. Куда писать, если что-то пошло не так

1. Запустить сервер с подробными логами:
   ```bash
   cd backend
   go run ./cmd/server 2>&1 | tee server.log
   ```
2. Если ошибка возникает в браузере — открыть DevTools (F12 →
   вкладка Console) и переслать разработчику текст ошибки + ссылку на
   страницу.
3. Логи Supabase — в панели Supabase, раздел **Logs**.
